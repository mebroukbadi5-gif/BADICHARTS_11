# QX SERVER v13.0 — Preload Engine + Live Streams

بعد الدخول مباشرة، السيرفر يجلب **300 شمعة لعملة `BRLUSD_otc`** (عملة فتح الشارت) مع **حالتها ونسبة دفعها**، ثم يجلب **300 شمعة لكل الأصول المفتوحة الأخرى واحدة تلو الأخرى**، ويشغّل **البث الحي لكل عملة** حتى يكون أي شارت تفتحه جاهزاً فوراً.

## ما الجديد في v13 (بطلب المستخدم)

| # | الميزة | التفاصيل |
|---|--------|----------|
| 1 | **عملة فتح الشارت** | `BRLUSD_otc` تُحمّل فوراً بعد الدخول: 300 شمعة + الحالة (مفتوح/مغلق) + نسبة الدفع + Turbo + 1M + 5M في لوحة خاصة |
| 2 | **تحميل بقية الأصول** | كل الأصول المفتوحة تتحمل واحدة تلو الأخرى: 300 شمعة لكل عملة (ثانية واحدة بين عملة وأخرى) |
| 3 | **بث حي دائم** | كل عملة محمّلة يبقى بث أسعارها يعمل داخلها — عندما تفتح أي شارت تجده جاهزاً |
| 4 | **التمرير للخلف** | `fetch_older_batch()` تجلب دفعة 170 شمعة أقدم، وكلما زاد التمرير تظهر شموع أخرى مثل المنصات الاحترافية. الدالة جاهزة الآن على الخادم — ربطها بالتطبيق يُضاف لاحقاً (ليس الآن) |
| 5 | **حماية القرص من التيكس** | التيكات في الذاكرة فقط (لا تُكتب على القرص أبداً) وتُحذف تلقائياً بعد **5 دقائق** |
| 6 | **حماية القرص من الشموع** | `candles.db` يُرمَّم كل ساعة (يحتفظ بأحدث 5000 شمعة لكل عملة) + ملف السجل يتدوّر عند 10MB |
| 7 | **كتابة HST أهدأ** | فاصل كتابة ملفات MT4 أصبح 1.0 ثانية (كان 0.2) — مع ~90 عملة متدفقة يبقى التحديث حياً دون إرهاق القرص |
| 8 | **حد الشموع في الذاكرة** | رُفع من 1000 إلى 3000 لكي تتراكم دفعات التمرير للخلف |

**طريقة الدخول وطريقة جلب الشموع الأصلية لم تُمَس إطلاقاً** — نفس `connect_quotex`، نفس جلسة الإيميل وكلمة المرور، نفس `CLIENT.get_candles`.

## التشغيل

```bash
pip install -r requirements_qx_server.txt
python qx_server_v13.py
```

1. يكتشف بلدك تلقائياً: بنغلاديش → `market-qx.info`، أي دولة أخرى → `quotex.com`.
2. يسأل فقط عن **البريد الإلكتروني وكلمة المرور** (يحفظ البريد للدخول التالي).
3. يطبع جدول كل العملات (الدفع + مفتوح/مغلق) في الترمينال ويعيد طبعه عند أي تغيير.
4. فوراً: `BRLUSD_otc` 300 شمعة + لوحة جاهزية، ثم بقية الأصول واحدة تلو الأخرى (ست Seeing رسائل `[preload i/total] SYMBOL: 300 candles + live stream ON`).

## النقطة الجاهزة لربط التطبيق لاحقاً

عند ربط التطبيق، هذه الدوال مستعدة داخل الملف (قسم SECTION 10):

```python
PAGINATION_API["fetch_older_batch"]("BRLUSD_otc")            # +170 شمعة أقدم (تمرير للخلف)
PAGINATION_API["fetch_older_batch"]("BRLUSD_otc", before_time=1730000000)
PAGINATION_API["get_recent_ticks"]("BRLUSD_otc", seconds=300) # تيكات آخر 5 دقائق (من الذاكرة)
PAGINATION_API["preload_status"]()                            # حالة التحميل المسبق لكل الأصول
```

كل دفعة تمرير للخلف تُدمج تلقائياً في: ذاكرة العملة + ملفات MT4 `.hst` + `candles.db`، فتظهر الشموع القديمة متراكمة مثل المنصات الاحترافية.

## أين تُحفظ البيانات؟

- `candles.db` بجانب الملف: كل الشموع (أحدث 5000 لكل عملة — ترميم تلقائي كل ساعة).
- ملفات `.hst` في مجلد MT4: تتحدث كل ثانية من البث الحي.
- `qx_assets_payouts.json`: لقطة العملات والدفع والحالة.
- التيكات: **الذاكرة فقط، تُحذف بعد 5 دقائق** — لا يوجد أي ملف تيكات على القرص.
- `qxchart.log`: يتدوّر تلقائياً عند 10MB (القديم يصبح `qxchart.old.log`).

## الإعدادات المهمة (أعلى الملف)

```python
PRELOAD_FIRST_SYMBOL = "BRLUSD_otc"   # عملة فتح الشارت
PRELOAD_CANDLES = 300                 # شموع التحميل الأولي لكل عملة
PAGINATION_BATCH = 170                # حجم دفعة التمرير للخلف
TICK_RETENTION_SECONDS = 300          # عمر التيك الأقصى (5 دقائق)
PRELOAD_REFRESH_INTERVAL = 900        # فحص الأصول المفتوحة/المغلقة كل 15 دقيقة
```

للخروج: `Ctrl+C`.
